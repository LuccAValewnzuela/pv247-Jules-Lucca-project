# Database Schema

All tables live in `src/db/schema/` (one file per table, re-exported from
`src/db/schema.ts`). Drizzle ORM with **SQLite** (libSQL) — a local `local.db`
file in development, a Turso database in production.

Conventions:

- Primary keys are `text` — 32-char random hex, generated by the database via
  `(lower(hex(randomblob(16))))`.
- Money is stored as integer **cents** (`priceCents`) to avoid floating-point issues.
- All timestamps are integer **unix epoch seconds**; Drizzle's
  `{ mode: "timestamp" }` maps them to JS `Date` objects.
- Auth uses **JWT sessions** — no auth/session tables are needed.
- Enums are `text` columns with a Drizzle `enum` option (a TypeScript union
  type, e.g. `"pending" | "confirmed" | ...`) — no DB-level enums in SQLite.
- Defaults use raw SQL (`unixepoch()`, `randomblob()`) so any insert path gets them.

## Entity overview

```
users 1───0..1 clients                         (a client may have an SSO account)
clients 1───* bookings                        (session history)
clients 1───* client_notes                    (dated private notes)
session_types 1───* bookings                  (price snapshotted on booking)
availability_blocks 1───* bookings            (booking time within block bounds)
bookings 1───0..1 bookings                    (rescheduledFrom audit trail)
blog_categories 1───* blog_posts
settings                                     (single row, bank details)
contact_messages                             (visitor contact form)
```

## `users` — `schema/users.ts`

SSO accounts (Google). A user is either a **client** or the **therapist**
(admin). Only one user should have the `therapist` role (enforced in app
logic — the therapist account is created by the seed script or manually).

| Field       | Type                | Constraints / notes                     |
| ----------- | ------------------- | --------------------------------------- |
| `id`        | text                | PK, default random hex                  |
| `email`     | text                | NOT NULL, unique — comes from the SSO   |
| `name`      | text                | NOT NULL — display name from the SSO    |
| `role`      | text enum           | NOT NULL, default `client` — `client` \| `therapist` |
| `createdAt` | integer timestamp   | NOT NULL, default `unixepoch()`         |

## `clients` — `schema/clients.ts`

Client records managed by the therapist. A client can exist **without a user
account** (created manually by the therapist, e.g. when booking on their
behalf) — in that case `userId` is null and `name`/`email` are entered by hand.

| Field       | Type              | Constraints / notes                                        |
| ----------- | ----------------- | ---------------------------------------------------------- |
| `id`        | text              | PK, default random hex                                      |
| `userId`    | text              | nullable, unique, FK → `users.id` — null = no account      |
| `name`      | text              | NOT NULL — kept in sync with the account when linked       |
| `email`     | text              | NOT NULL — required for notifications (also of unlinked clients) |
| `phone`     | text              | nullable                                                    |
| `feedToken` | text              | NOT NULL, unique — 64-char random hex, DB default. Secret token for the `.ics` feed URL |
| `createdAt` | integer timestamp | NOT NULL, default `unixepoch()`                             |

Note: `feedToken` powers `api/calendar/[token]` — the client subscribes in
Google Calendar with a URL containing their token; no auth header possible
there.

## `session_types` — `schema/sessionTypes.ts`

Session types offered by the therapist, each with its own price and duration.
The **format** (in person / online) is chosen at booking time, not here.

| Field              | Type              | Constraints / notes                              |
| ------------------ | ----------------- | ------------------------------------------------ |
| `id`               | text              | PK, default random hex                            |
| `name`             | text              | NOT NULL — e.g. "Initial consultation"            |
| `description`      | text              | NOT NULL — shown on the pricing page              |
| `durationMinutes`  | integer           | NOT NULL                                          |
| `priceCents`       | integer           | NOT NULL                                          |
| `isActive`         | integer boolean   | NOT NULL, default true — soft-archive instead of delete, so historical bookings stay consistent |
| `createdAt`        | integer timestamp | NOT NULL, default `unixepoch()`                   |

## `availability_blocks` — `schema/availabilityBlocks.ts`

Time blocks the therapist publishes as available. The client picks a start
time **within** a block; a single block can contain multiple bookings
(validation is app logic: booking start/end must lie inside the block, must
not overlap other bookings).

| Field       | Type              | Constraints / notes                     |
| ----------- | ----------------- | --------------------------------------- |
| `id`        | text              | PK, default random hex                   |
| `startsAt`  | integer timestamp | NOT NULL                                 |
| `endsAt`    | integer timestamp | NOT NULL — `endsAt > startsAt` in app logic |
| `createdAt` | integer timestamp | NOT NULL, default `unixepoch()`          |

## `bookings` — `schema/bookings.ts`

The core entity. State machine: `pending → confirmed → completed`, or
`cancelled` from pending/confirmed.

| Field                 | Type              | Constraints / notes                                        |
| --------------------- | ----------------- | ---------------------------------------------------------- |
| `id`                  | text              | PK, default random hex                                      |
| `clientId`            | text              | NOT NULL, FK → `clients.id`                                 |
| `sessionTypeId`       | text              | NOT NULL, FK → `session_types.id`                           |
| `availabilityBlockId` | text              | NOT NULL, FK → `availability_blocks.id` — the block the time was picked from |
| `priceCents`          | integer           | NOT NULL — **snapshot** of the type's price at booking time, so later price changes don't rewrite history |
| `format`              | text enum         | NOT NULL — `in_person` \| `online`                          |
| `startsAt`            | integer timestamp | NOT NULL                                                    |
| `endsAt`              | integer timestamp | NOT NULL — computed as start + duration at creation         |
| `status`              | text enum         | NOT NULL, default `pending` — `pending` \| `confirmed` \| `completed` \| `cancelled` |
| `videoCallUrl`        | text              | nullable — generated when `format = online` (e.g. a meet link) |
| `cancelledBy`         | text enum         | nullable — `client` \| `therapist`; set only when cancelled |
| `cancelledAt`         | integer timestamp | nullable                                                    |
| `rescheduledFromId`   | text              | nullable, FK → `bookings.id` (self) — points at the original booking when the therapist reschedules |
| `notes`               | text              | nullable — client's note or therapist's internal note        |
| `createdAt`           | integer timestamp | NOT NULL, default `unixepoch()`                              |
| `updatedAt`           | integer timestamp | NOT NULL, default `unixepoch()` — set by app on changes     |

Business rules kept in **app logic**, not the schema:

- Client cancellation only ≥ 48 h before `startsAt`.
- Booking time must lie within its availability block and not overlap
  existing bookings.
- `rescheduledFromId`: when rescheduling, the original booking is cancelled
  (with `rescheduledFromId` on the new one) — keeps a full audit trail.

## `settings` — `schema/settings.ts`

Single-row table (id is always `1`) holding the therapist's business and bank
details shown to clients alongside a booking's payment QR code. There is **no
online payment** — the client pays by bank transfer.

| Field          | Type              | Constraints / notes                                  |
| -------------- | ----------------- | ---------------------------------------------------- |
| `id`           | integer           | PK — fixed value `1` (single row, default 1)          |
| `businessName` | text              | NOT NULL — shown on invoices / payment instructions   |
| `iban`         | text              | NOT NULL — for the bank transfer QR (SEPA)            |
| `bankAccount`  | text              | nullable — local account number, if shown             |
| `bankName`     | text              | nullable                                              |
| `updatedAt`    | integer timestamp | NOT NULL, default `unixepoch()`                       |

The QR code itself is generated on the fly from IBAN + amount + payment
reference (booking id) — not stored.

## Migrations & seed workflow

```bash
npm run db:generate   # generate SQL migration in ./drizzle from schema changes
npm run db:migrate    # apply migrations to the DB in DATABASE_URL
npm run db:push       # alternative: push schema directly (quick local iteration)
npm run db:seed       # insert demo data (therapist user, session types, settings, blog) — idempotent
npm run db:studio     # browse the database in Drizzle Studio
```

`DATABASE_URL=file:local.db` for local development (the `local.db` file is
git-ignored); in production set it to your Turso database URL plus
`DATABASE_AUTH_TOKEN`.
